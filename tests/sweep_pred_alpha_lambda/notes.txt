========================================================================
 alpha x lambda sweep: the four prediction demons
========================================================================

QUESTION
  The prediction demons still use the alpha/lambda they were first given (commit 4167fe2) and their
  error stops improving after ~250k steps. Would a better alpha or lambda lower the error, as it did
  for the control demons (tests/sweep_alpha_lambda)?

ANSWER
  No. Across 20 settings per demon the best error at 1M is within 1-8% of the current setting, which
  is within the eval-to-eval scatter (~0.1-0.2). Keep the current values. The error is not noise in
  the target (the return is nearly deterministic), so the limit is most likely the tile features.

  Evaluation    every 100k: 100 fixed visited states (non-terminal), picked at the first eval.
                True return per state computed once: mean of 5 rollouts of the fixed target action
                (horizon 400, same as main.evaluate). Score = mean |prediction - return| over the states.
  Why one target per state is enough: the target policy is a fixed action and physics has no noise;
                only sensor noise (sd 0.005) varies the return. Measured on the 3M checkpoint, the return's
                sd over 10 rollouts was 0.008 / 0.315 / 0.022 / 0.000 (obstacle / stop / light / bump).
  Current settings: steps-to-obstacle and steps-to-stop alpha 0.3, lambda 0.4;
                    light-if-forward and bump-soon alpha 0.2, lambda 0.4.

------------------------------------------------------------------------
CONCLUSIONS
------------------------------------------------------------------------
  - No setting clearly beats the current one: the best gain is 1-8%, smaller than the scatter
    between consecutive evals of one setting (e.g. obstacle 1.99 -> 2.26 from 900k to 1M).
  - Small alpha (0.03) with lambda 0 is clearly worse (slow); alpha 1.0 is worse everywhere and
    diverged at lambda 0.9 for steps-to-obstacle and steps-to-stop.
  - Longer traces (lambda 0.7-0.9) help a little at small alpha, as expected for multi-step returns.
  - [inference] Since the target return is nearly deterministic and no step size helps, the error
    floor comes from the tile features (states with different returns sharing tiles). Checking which
    features steps-to-obstacle relies on (forward IR resolution) is the next step if the error matters.

CAVEATS
  - One seed only (by request): differences of a few percent are not reliable.
  - 1M steps from zero weights; the final run is 3M, where the current settings sit at the same level
    (final train_log: last 10 evals obstacle 1.91, stop 0.83, light 0.89, bump 0.69 on 25 random states).

WHAT IT LED TO
  - Prediction demon settings left unchanged in demons.py.

HOW TO REPRODUCE
------------------------------------------------------------------------
  From a folder inside the code directory (one process per demon, they run in parallel):
      PYTHONPATH=.. python3 -u sweep_pred.py steps-to-obstacle > sweep_pred_steps-to-obstacle.txt
  likewise for steps-to-stop, light-if-forward, bump-soon. About 40 min each.
