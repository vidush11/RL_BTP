========================================================================
 Final run: off-policy Horde vs on-policy Sarsa(lambda), frozen env, 3M steps each
========================================================================

QUESTION
  With the environment frozen and all fixes in, how does one off-policy Horde (7 demons, one behaviour
  stream) compare with a separate on-policy learner per control demon, on identical evaluation?

ANSWER
  The Horde beats plain on-policy on all three control demons. Episodic on-policy (random restarts every
  250 steps) beats the Horde on seek-light (13.5x vs 7.2x random) and ties avoid and spin, but needs
  resets and one run per demon; the Horde learned all 7 demons from one unbroken stream.

------------------------------------------------------------------------
SETUP
------------------------------------------------------------------------
  Date          2026-11-12, run in ../code2-runs/final (code identical to the repo's at the time)
  Env           env.py frozen: 3x3 m, 2 pillars, light at (0.4, 2.6), hard shadows,
                brightness 0.25/(0.25+d^2), 0.5 s per step, sensor noise sigma 0.005 (not on bump)
  Horde         main.py: 7 demons, GQ(lambda), sticky-random behaviour (STICK 0.8), stopped at 3M
                (STEPS in main.py is 12M). Control demons alpha 0.1, lambda 0.3 (tests/sweep_alpha_lambda);
                trace uses min(1, rho) (tests/horde_diverged_trace_rho)
  On-policy     runs/onpolicy_used.py: Sarsa(lambda), accumulating trace, one run per control demon,
                same tile features; lambda 0.9, alpha 0.05/N_ACTIVE, eps 0.1, gamma 0.95, 3M steps
                (ran to 1M, then resumed from the 1M checkpoint to 3M)
                  plain:    the robot follows its own eps-greedy policy, one continuous life
                  episodic: every 250 steps jump to a random free spot + heading, trace zeroed,
                            no update across the jump
  Evaluation    identical for all: main.EVAL_STARTS (100 states of a sticky-random run, seed 1234),
                250 greedy steps each, learning off, every 25k steps, sensor noise seed SEED+t+1;
                random baseline main.random_rewards (CHANCE at run time) computed once on the same starts
  Metrics       x random = learned reward/step / random reward/step
                scaled (0-1) = reward scaled by each reward's range (seek 0 to sqrt 2, avoid -1 to 1, spin 0 to 1)
                steps to competence = first step where the trailing 100k mean covers 90% of the gap from
                random to the run's own final level (final = mean of the last 8 evals)

------------------------------------------------------------------------
CONCLUSIONS
------------------------------------------------------------------------
  - Plain on-policy seek parks at the light (97.5% of steps within 0.5 m, mid-run diagnosis), so it rarely
    practises from the dark: 0.068 from dark starts vs 0.407 off-policy. Episodic restarts fix the coverage.
  - Episodic on-policy beats the Horde on seek-light, ties avoid, is slightly below on spin.
  - The Horde reaches its level more slowly on seek (1.125M vs 425k episodic) but needs no resets.
  - Sum w=0.25 is the best combination: more light than seek alone (0.659 vs 0.595), a tenth of the bumps
    (41.9 vs 424.5 per 1k), ends near the light more often (84% vs 78%). Reflex switches did worse than the sum.
  - Fig 6: the seek demon's front light ~0.7 vs ~0.1 for the behaviour (read off fig6_light_seeking.png).

CAVEATS
  - One seed per learner.
  - Prediction MAE is a single eval of 25 states.
  - The three plain on-policy runs have per-start scores only from 1.025M on (they started before
    per-start saving existed).

HOW TO REPRODUCE
------------------------------------------------------------------------
  Horde:      from a run folder, python3 -u <code>/main.py (stop at 3M)
  On-policy:  cd onpolicy_<demon> && PYTHONPATH=<code> python3 -u <code>/onpolicy/onpolicy.py <demon> [episodic]
              (<demon> = seek, avoid or spin; run from the folder so checkpoint and logs land there)
  Figures:    PYTHONPATH=<code2-runs> python3 final_figures.py <code2-runs>/final
